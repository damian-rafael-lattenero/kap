Raise

interface Raise<in E>

The raise world — direct-style typed errors over Either

Companion to validated (the Kap world, NonEmptyList channel): Raise is the PLAIN world with a SINGLE error channel — the Arrow Raise shape, expressed with kap's own control-flow machinery. No coroutine is required; either is a pure value function, and eitherSuspend is its suspend boundary for workflows that call suspend steps.

Reusable steps are extensions on Raise — they resolve inside the blocks exactly like the built-in operators:

fun Raise<ParseError>.trimNonBlank(s: String): String {
    ensure(s.isNotBlank()) { ParseError.BlankName }
    return s.trim()
}

NOTE: Kotlin context-parameter functions do NOT resolve inside the blocks (2.4 limitation measured while building this DSL) — use extensions on Raise for the same ergonomics. Give the result an EXPECTED TYPE (a typed val or the function return type) so E flows into the block — the Arrow-docs idiom; a bare expression-position either { ... } infers E from its own body first and may need explicit type arguments.

Error semantics: SHORT-CIRCUIT. The first raise abandons the rest of the block. Bugs and kotlinx.coroutines.CancellationException are never captured — the builders only intercept their own control-flow exception, so the CE law (cancellation is sacred) is structural here, not a catch arm to forget.
