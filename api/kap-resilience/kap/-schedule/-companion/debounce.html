fun <A> debounce(n: Int, isQuiet: (A) -> Boolean): Schedule<A>

The quiet-window stop condition: keep going while the work keeps coming, and stop once n consecutive inputs have reported quiet.

This is the lawful home of the "drain until quiet" loop. A polling body returns what it found (a count, a Progress, anything isQuiet can read); the schedule ends the loop exactly when the quiet window fills. Compose it with a cadence by and — the cadence supplies the delays, the window supplies the stop:

// Poll every 50 ms until three consecutive polls come back empty
Kap { poll() }
    .repeat(Schedule.spaced<Int>(50.milliseconds) and Schedule.debounce(3))

Laws

For a fresh instance and the input sequence a0, a1, ...:

LawProperty
Stop at the filled windowDecision.Done exactly when the run of quiet inputs ending at ai is >= n

Empty windowdebounce(0, isQuiet) decides exactly like never (Done at attempt 0)
Singleton windowdebounce(1, isQuiet) decides exactly like doUntil(isQuiet)

Because every Continue delay is ZERO, cadence and debounce(n) keeps the cadence's delays exactly (max(d, 0) == d) and is Done when either operand is: the window is a stop condition, not a clock. Property-tested in ScheduleDebounceLawsTest.

Statefulness. Unlike the pointwise factories the semiring laws range over, debounce remembers its quiet run: the decision depends on the inputs this instance has already seen, exactly like withMaxDuration's clock. Build one fresh instance per run and never share an instance between concurrent drivers.

Return

a schedule that continues with no delay until the window fills.

Parameters

n

the window: how many consecutive quiet inputs end the loop. 0 stops immediately — the first decision is Decision.Done.

isQuiet

reads one input as "this attempt found no work".

Throws

IllegalArgumentException

when n is negative.
