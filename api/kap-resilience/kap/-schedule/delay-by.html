delayBy

fun delayBy(f: (A) -> Duration): Schedule<A>

Derives each Continue delay from the schedule's input: the Continue/Done decision and the attempt count are unchanged, but every Continue delay is replaced by f(input).

The delay becomes a function of the failure (or value) driving the decision — e.g. longer waits for a rate-limit error than for a transient timeout — without touching the stop condition:

Schedule.forever<Throwable>()
    .delayBy { error -> if (error is RateLimited) 30.seconds else 500.milliseconds }
Content copied to clipboard

f is only called when the original schedule says Decision.Continue; a Decision.Done result is passed through untouched. A negative result is a programming error and fails fast with IllegalArgumentException instead of being silently coerced to zero.

Return

a schedule with the same Continue/Done decisions and f-derived delays.

Parameters

f

computes the wait for the current input.

Throws

IllegalArgumentException

when f produces a negative delay.
