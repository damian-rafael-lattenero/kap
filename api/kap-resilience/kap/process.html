process

fun <A> Kap<A>.process(name: String, restart: RestartPolicy = RestartPolicy.exponential(), heartbeatEvery: Duration = 1.seconds, onRestart: (attempt: Int, error: Throwable, nextDelay: Duration) -> Unit = { _, _, _ -> }, onHeartbeat: () -> Unit = {}, timeSource: TimeSource = TimeSource.Monotonic): Process<A>

Lifts this computation into a supervised, named Process — the SPEC-5.0 milestone 4.2 first cut: a repeated Kap with a restart policy, health, and a handle with stop(). Nothing runs until Process.startIn.

Semantics:

  • the body completing normally finishes the process (transient semantics: a long-lived service body should not return);

  • a failure restarts after the policy's delay, up to its cap, then ProcessHandle.await throws ProcessExhaustedException;

  • stop() and scope cancellation are never failures (no restart, no exhaustion);

  • the heartbeat beats at heartbeatEvery independent of body progress (ZERO disables it);

  • onRestart/onHeartbeat are transparent observers.

Parameters

name

process name, surfaced in the handle and terminal exceptions.

restart

delays between restarts and the restart cap; the factories enforce the convergence law (positive delays, finite cap).

heartbeatEvery

beat period while the process is alive; ZERO disables.

onRestart

observer invoked before each restart delay (attempt number, the failure, the delay about to be waited).

onHeartbeat

observer invoked on every beat.

timeSource

injectable time source for ProcessHandle.heartbeatAge.
